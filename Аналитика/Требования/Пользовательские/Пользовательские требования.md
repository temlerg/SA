# 📌 Что такое пользовательские требования

**Пользовательские требования** — это описание того, _что пользователь хочет и должен иметь возможность делать_ в системе. Они описывают цели, задачи и поведение системы с точки зрения конечного пользователя.

---

## 💬 Примеры пользовательских требований

- Пользователь должен иметь возможность просматривать список заказов
    
- Пользователь может отменить заказ, если он ещё не подтверждён
    
- Пользователь должен получать уведомление при изменении статуса доставки
    
- Пользователь должен иметь возможность восстановить пароль через email
    

---

## 🧱 Структура пользовательского требования

1. **Идентификатор** — например, UR-001
    
2. **Роль** — кто будет использовать функцию (например, клиент, администратор)
    
3. **Цель** — что хочет достичь пользователь
    
4. **Действие** — какие шаги предпринимает
    
5. **Ожидаемый результат** — что система должна сделать в ответ
    

---

## 🧩 User Story как способ формализации

Часто пользовательские требования оформляются в виде **User Story**:

```
Как [роль], я хочу [действие], чтобы [цель].
```

**Пример:**  
Как _покупатель_, я хочу _видеть статус моего заказа_, чтобы _понимать, когда ожидать доставку_.

Дополняется **критериями приёмки (Acceptance Criteria)**:

- Статус отображается на странице заказа
    
- Статус обновляется автоматически при изменении на сервере
    
- Пользователь получает push-уведомление при изменении статуса

## 🧩 Где фиксируются пользовательские требования

- В backlog в виде User Story (Jira, Trello, YouTrack)
    
- В техническом задании или Product Requirements Document
    
- В прототипах (например, Figma, Miro), если описаны действия
