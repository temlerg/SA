## Структура и оглавление

1. **Общие сведения о SQL**  
    Определение языка: SQL (Structured Query Language) — декларативный язык запросов для работы с реляционными базами данных. Основные компоненты: сервер СУБД, клиентские приложения, схемы и объекты БД. Архитектурный обзор: клиент отправляет запрос, сервер анализирует, строит план выполнения, оптимизирует и выполняет.
    
2. **Типы данных**  
    Полный перечень и назначение:
    
    - **Числовые**: INTEGER (целые), NUMBER или DECIMAL (точные значения с фиксированной точкой), FLOAT (числа с плавающей точкой). Особенности хранения, диапазоны значений и точность при вычислениях.
        
    - **Символьные**: CHAR (фиксированная длина), VARCHAR2 (переменная длина), NCHAR/NVARCHAR2 (национальные форматы). Кодировка символов, влияние на производительность, различие между байтовой и символьной длиной.
        
    - **Дата/время**: DATE (дата и время без часового пояса), TIMESTAMP (доля секунды), TIMESTAMP WITH TIME ZONE (зона), TIMESTAMP WITH LOCAL TIME ZONE (локализация). INTERVAL DAY TO SECOND (промежуток времени с точностью до секунды), INTERVAL YEAR TO MONTH (интервал лет и месяцев). Форматы ввода и вывода, типичные функции и представления.
        
    - **LOB (Large Object)**: CLOB (символьные большие объекты), BLOB (бинарные), NCLOB (национальные). Схемы хранения (inline, LOB сегменты), лимиты размера, методы работы (DBMS_LOB).
        
    - **Другие специализированные типы**: BOOLEAN (примитивный логический), RAW (необработанные байты), XMLType (XML-документы). Ограничения и сценарии применения.
        
3. **Операторы DDL (Data Definition Language)**  
    3.1. **CREATE**
    
    - Создание нового объекта: таблицы, схемы, базы данных, индекса, представления, синонима, последовательности, триггера, профиля, роли.
        
    - Основные параметры команды: указание названия и структуры таблицы (имен столбцов с типами, ограничений), схемы и пространства таблиц (TABLESPACE).
        
    - Принципы безопасности: доступ к CREATE ограничивается привилегиями, схемы по умолчанию.
        
    
    3.2. **ALTER**
    
    - Изменение существующей структуры: добавление, удаление и изменение столбцов (ALTER TABLE ADD/DROP/MODIFY COLUMN), переименование объектов (RENAME), изменение ограничений (ADD/DROP CONSTRAINT).
        
    - Порядок выполнения и замена: блокировка таблицы, влияние на доступность, возможность онлайн-изменений для крупных БД.
        
    - Особенности: изменение размера столбца, изменение типа данных, перенос в другой Tablespace.
        
    
    3.3. **DROP**
    
    - Удаление объектов: таблицы (DROP TABLE), схемы (DROP USER CASCADE), базы данных (DROP DATABASE), индексов (DROP INDEX), представлений (DROP VIEW), синонимов (DROP SYNONYM), последовательностей (DROP SEQUENCE), триггеров (DROP TRIGGER).
        
    - Cascade-удаление зависимых объектов, предупреждения об уничтожении данных.
        
    - Безвозвратность: необходимость резервного копирования.
        
    
    3.4. **TRUNCATE**
    
    - Быстрая очистка таблицы без удаления самой структуры.
        
    - Различие от DELETE: невозможно откатить (DML), операция DDL, обнуление индексных и статистических данных.
        
    - Переиндексация после очистки, запись в журнал минимальна.
        
4. **Операторы DML (Data Manipulation Language)**  
    4.1. **SELECT**
    
    - Основная команда для выборки данных.
        
    - Синтаксис: SELECT [DISTINCT] список_выражений FROM список_таблиц [WHERE условие] [GROUP BY список_столбцов] [HAVING условие] [ORDER BY список_столбцов [ASC|DESC]] [FETCH FIRST n ROWS ONLY].
        
    - Порядок логической обработки: 1) FROM (обзвон таблиц и соединений), 2) WHERE (фильтрация), 3) GROUP BY (группировка), 4) HAVING (фильтрация групп), 5) SELECT (построение набора столбцов), 6) ORDER BY (сортировка), 7) FETCH (ограничение числа строк).
        
    - Ключевые понятия: корреляция, картезианское произведение при отсутствии условий соединения, вложенные (под)запросы в блоках SELECT.
        
    
    4.2. **INSERT**
    
    - Вставка единственной строки: указание значений через VALUES или использование DEFAULT.
        
    - Вставка из другой таблицы: INSERT INTO таблица (столбцы) SELECT ... FROM ...; обеспечивает массовую загрузку данных.
        
    - Поведение при нарушении ограничений: ошибка UNIQUE/PRIMARY KEY, значение NULL в NOT NULL.
        
    
    4.3. **UPDATE**
    
    - Обновление определённых строк: UPDATE таблица SET столбец1 = выражение1 [, столбец2 = выражение2 ...] [WHERE условие].
        
    - Использование подзапросов для задания новых значений: безопасное обновление на основе других таблиц.
        
    - Воздействие на индексы: при изменении индексируемого столбца перестраивается индекс, возможны блокировки строк.
        
    
    4.4. **DELETE**
    
    - Удаление строк: DELETE FROM таблица [WHERE условие].
        
    - Условие WHERE определяет, какие строки будут удалены; без WHERE удаляются все.
        
    - Отличие от TRUNCATE: DELETE — DML, можно откатить; при удалении большого числа строк возможны длительные операции в журнале.
        
    
    4.5. **MERGE**
    
    - Объединение операций INSERT и UPDATE: синтаксис MERGE INTO target_table USING source_table ON (условие совпадения) WHEN MATCHED THEN UPDATE SET ... WHEN NOT MATCHED THEN INSERT (...).
        
    - Применение для синхронизации данных из внешних источников, выгрузок, ETL-процессов.
        
    - Особенности производительности: единая операция, уменьшает число обращений.
        
5. **Подзапросы**  
    5.1. **Некоррелированные (несвязанные)**
    
    - Определение: независимый запрос, не взаимодействующий с основной таблицей.
        
    - Пример: использование в условии WHERE столбца IN (результат подзапроса).
        
    - Выполнение: один раз перед выполнением основного запроса, кешируется.
        
    
    5.2. **Коррелированные (связанные)**
    
    - Определение: подзапрос внутри основного, ссылается на поля из внешнего запроса.
        
    - Пример: проверка существования строк в другой таблице для каждой строки основного набора.
        
    - Выполнение: подзапрос выполняется для каждой строки внешнего запроса, может работать медленнее.
        
    
    5.3. **Операторы сравнения с подзапросами**
    
    - **IN**: проверка наличия значения в списке результатов.
        
    - **ANY/SOME**: сравнение с любым значением из набора (>, <, =).
        
    - **ALL**: сравнение с каждым значением из набора; условие истинно, если выполняется для всех.
        
    - **EXISTS**: проверка существования хотя бы одной строки, быстрый способ определить наличие.
        
    
    _Принципы использования: оптимизация для больших наборов данных, эквивалентность с JOIN и предпочтения в плане выполнения._
    
6. **Объединение результатов нескольких запросов**  
    6.1. **UNION / UNION ALL**
    
    - **UNION**: объединяет результаты двух или более SELECT, удаляя дубликаты, сортировка окончательного набора.
        
    - **UNION ALL**: сохраняет все строки, включая дубликаты; быстрее за счёт отсутствия операции DISTINCT.
        
    
    6.2. **INTERSECT**
    
    - Возвращает строки, присутствующие в каждом из указанных наборов результатов.
        
    - Требования: одинаковое число и совместимые типы столбцов.
        
    
    6.3. **MINUS**
    
    - Возвращает строки из первого набора, которых нет во втором.
        
    - Аналог относительно первого набора; порядок столбцов и типы должны совпадать.
        
    
    _Важные нюансы: при использовании ORDER BY в конце всего выражения, влияние на производительность, необходимость сортировки._
    
7. **Соединение таблиц (JOIN)**  
    7.1. **INNER JOIN**
    
    - Возвращает только те строки, для которых выполнено условие соединения.
        
    - Синтаксис: SELECT ... FROM таблица1 INNER JOIN таблица2 ON таблица1.col = таблица2.col.
        
    
    7.2. **LEFT/RIGHT/FULL OUTER JOIN**
    
    - **LEFT**: все строки из левой таблицы и совпадающие из правой; незаполненные столбцы правой таблицы получают NULL.
        
    - **RIGHT**: аналогично, но для правой таблицы.
        
    - **FULL**: объединяет результаты LEFT и RIGHT, сохраняет все строки обеих таблиц.
        
    
    7.3. **CROSS JOIN**
    
    - Декартово произведение: каждая строка первой таблицы соединяется с каждой строкой второй.
        
    - Используется редко, когда нужен полный набор комбинаций.
        
    
    7.4. **Self-Join**
    
    - Соединение таблицы самой с собой: применяется для иерархических структур (например, сотрудник-менеджер), требуя алиасы для двух экземпляров таблицы.
        
    
    _Условия соединения: равенства, неравенства, диапазоны; влияние кардинальности и индексов на выбор плана._
    
8. **Агрегатные функции и GROUP BY / HAVING**
    
    - **COUNT(expr)**: количество строк, подходящих под условие.
        
    - **SUM(expr)**: сумма значений числового выражения.
        
    - **AVG(expr)**: среднее арифметическое.
        
    - **MIN(expr)/MAX(expr)**: минимальное и максимальное значение.
        
    - **GROUP BY**: группирует строки по указаниям столбцов, используется вместе с агрегатами.
        
    - **HAVING**: фильтрация уже сгруппированных данных на основе агрегатных условий.
        
    
    _Правила: в SELECT перечне должны быть или агрегатные функции, или столбцы из GROUP BY. HAVING выполняется после группировки, WHERE — до._
    
9. **Функции и выражения**  
    9.1. **Строковые функции**
    
    - **CONCAT**: объединение строк; эквиваленты оператору ||.
        
    - **SUBSTR (или SUBSTRING)**: извлечение части строки по позициям.
        
    - **LENGTH (или LEN)**: длина строки (байты/символы).
        
    - **REPLACE**: замена подстроки на другую.
        
    - **TRIM/LTRIM/RTRIM**: удаление пробелов или указанных символов с конца/начала строки.
        
    
    9.2. **Числовые функции**
    
    - **ROUND(expr, precision)**: округление до указанной точности.
        
    - **TRUNC(expr, precision)**: усечение без округления.
        
    - **NVL(expr1, expr2)**: замена NULL на указанное значение.
        
    - **DECODE(expr, search, result, [searchN, resultN], default)**: аналог CASE для быстрого ветвления.
        
    
    9.3. **Дата/время функции**
    
    - **SYSDATE**: текущая дата и время сервера.
        
    - **CURRENT_TIMESTAMP**: текущая временная метка с часовым поясом.
        
    - **EXTRACT(field FROM datetime)**: извлечение части (YEAR, MONTH, DAY, HOUR, MINUTE, SECOND).
        
    - **ADD_MONTHS(date, n)**, **MONTHS_BETWEEN(date1, date2)**: арифметика дат.
        
    - **TRUNC(date, format)**: усечение даты до дня/месяца/года.
        
    
    9.4. **CASE выражения**
    
    - **Простая форма**: CASE expr WHEN value1 THEN result1 WHEN value2 THEN result2 ELSE default END.
        
    - **Поисковая форма**: CASE WHEN condition1 THEN result1 WHEN condition2 THEN result2 ELSE default END.
        
    - Применение внутри SELECT, ORDER BY, HAVING для гибкой логики.
        
10. **Представления (Views)**
    
    - **Определение**: виртуальная таблица, сохраняющаяся в каталоге, но данные не хранятся физически.
        
    - **CREATE VIEW имя AS SELECT ...**: формирование представления на основе запроса; указание WITH CHECK OPTION при необходимости сохранения ограничений.
        
    - **ALTER VIEW имя AS SELECT ...**: изменение определения.
        
    - **DROP VIEW имя**: удаление.
        
    - **Обновляемость**: обновляемые представления (одна таблица, простые вычисления) vs. сложные (агрегации, объединения) не обновляемые.
        
    - **Безопасность**: ограниченный доступ к данным, использование синонимов для абстрагирования схем.
        
11. **Индексы**
    
    - **B-tree** (основной): сбалансированное дерево, эффективность при точном и диапазонном поиске, минимальная глубина.
        
    - **Bitmap**: битовые карты для столбцов с низкой кардинальностью (пол, статус), эффективны при аналитических запросах, но медленны при частых DML.
        
    - **Составные индексы**: индекс на несколько столбцов, порядок столбцов влияет на использование.
        
    - **Уникальные индексы**: обеспечивают уникальность значений, автоматически создаются для PRIMARY KEY и UNIQUE.
        
    - **Управление**: CREATE INDEX, ALTER INDEX REBUILD/COALESCE, DROP INDEX.
        
    - **Влияние на производительность**: ускоряют выборки, замедляют вставку/обновление/удаление при больших объёмах DML.
        
12. **Ограничения (Constraints)**
    
    - **PRIMARY KEY**: набор столбцов, уникально идентифицирующих строку; не допускает NULL; автоматически создаёт уникальный индекс.
        
    - **FOREIGN KEY**: ссылка на PRIMARY KEY другой таблицы; обеспечивает ссылочную целостность; при удалении/обновлении каскадные или ограничительные действия (ON DELETE CASCADE, ON UPDATE CASCADE).
        
    - **UNIQUE**: обеспечивает уникальность значений в столбце(ах) без автоматического создания первичного ключа.
        
    - **CHECK**: возвращает TRUE/FALSE на основе выражения; используется для контроля диапазонов и условий.
        
    - **NOT NULL**: запрещает хранение NULL, применяется на уровне столбца.
        
    - **Способы задания**: внутри CREATE TABLE (INLINE) и через ALTER TABLE ADD CONSTRAINT.
        
13. **Транзакции и управление ими**
    
    - **Транзакция**: последовательность операций DML, выполняемая как единое целое.
        
    - **ACID**:
        
        - **Атомарность (Atomicity)**: все операции транзакции должны выполниться полностью или не выполниться вовсе.
            
        - **Консистентность (Consistency)**: переход из одного корректного состояния БД в другой; все ограничения должны соблюдаться.
            
        - **Изоляция (Isolation)**: параллельные транзакции не влияют друг на друга (уровни изоляции: READ UNCOMMITTED, READ COMMITTED, REPEATABLE READ, SERIALIZABLE).
            
        - **Долговечность (Durability)**: после фиксации (COMMIT) изменения сохраняются, даже при сбоях.
            
    - **Команды управления**:
        
        - **COMMIT**: фиксирует изменения, делает их видимыми для других транзакций.
            
        - **ROLLBACK**: отменяет все изменения, выполнённые с начала транзакции или после последнего SAVEPOINT.
            
        - **SAVEPOINT имя**: устанавливает промежуточную точку для частичного отката.
            
14. **Секвенции**
    
    - **Создание**: CREATE SEQUENCE имя [START WITH n] [INCREMENT BY n] [MAXVALUE n | NOMAXVALUE] [MINVALUE n | NOMINVALUE] [CYCLE | NOCYCLE] [CACHE n | NOCACHE] [ORDER | NOORDER].
        
    - **NEXTVAL**: получение следующего значения из последовательности, используется в INSERT.
        
    - **CURRVAL**: текущее значение последовательности в сессии.
        
    - **Параметры**: шаг (INCREMENT), схема кэширования, циклическое повторение.
        
15. **Синонимы (Synonyms)**
    
    - **Определение**: альтернативное имя для объекта БД (таблица, представление, последовательность, процедура), используется для упрощения доступа.
        
    - **LOCAL SYNONYM**: доступен только в схеме создателя; ссылка на объект в той же или внешней схеме.
        
    - **PUBLIC SYNONYM**: создаётся администратором, доступен всем пользователям; скрывает схему источника.
        
    - **CREATE SYNONYM имя FOR схема.объект; DROP SYNONYM имя.**
        
16. **Триггеры**
    
    - **Определение**: хранимая процедура, автоматически выполняющаяся при событиях DML (INSERT, UPDATE, DELETE) или событиях схемы (DDL, вместо представлений).
        
    - **Типы триггеров**:
        
        - **BEFORE INSERT/UPDATE/DELETE**: выполнение до изменения данных, используется для проверки и модификации значений.
            
        - **AFTER INSERT/UPDATE/DELETE**: выполнение после, подходит для журналирования и каскадных действий.
            
        - **INSTEAD OF**: для представлений, заменяет действие, позволяя обновлять сложные VIEW.
            
    - **Области применения**:
        
        - **Row-Level**: выполняется для каждой строки (FOR EACH ROW), доступ к OLD и NEW значениям.
            
        - **Statement-Level**: выполняется один раз для всего оператора.
            
    - **Ограничения**: рекурсивные вызовы, порядок выполнения нескольких триггеров.
        
17. **Нормализация данных**
    
    - **Цель**: снижение избыточности, предотвращение аномалий при вставке, обновлении и удалении.
        
    - **Формы нормализации**:
        
        - **1NF (Первая нормальная форма)**: все атрибуты атомарны, нет повторяющихся групп.
            
        - **2NF (Вторая нормальная форма)**: таблица находится в 1NF, и все неключевые атрибуты полностью зависят от всего составного ключа.
            
        - **3NF (Третья нормальная форма)**: таблица в 2NF, и нет транзитивной зависимости между неключевыми атрибутами (каждый неключевой атрибут зависит только от ключа).
            
    - **Дополнительные формы** (опционально):
        
        - **BCNF (Нормальная форма Бойса-Кодда)**: усиленная версия 3NF, где для каждой функциональной зависимости X → Y, X должна быть суперключом.
            
        - **4NF, 5NF**: редкие случаи, связанные с многозначными зависимостями и джойнами.
            
18. **Права доступа и безопасность**
    
    - **GRANT**: предоставление конкретных привилегий на объекты (SELECT, INSERT, UPDATE, DELETE, EXECUTE и др.) или ролей целиком.
        
    - **REVOKE**: отзыв ранее выданных привилегий; каскадное ограничение: может потребовать удаления наследуемых прав.
        
    - **Роли (Roles)**: объединение привилегий, назначенных группе пользователей; облегчает управление безопасностью.
        
    - **Профили**: ограничение ресурсов (CPU, логин-время), контроль паролей (длинна, срок действия).
        
    - **Аудит (Audit)**: включение мониторинга операций (логирование действий пользователя, успешные и неуспешные попытки доступа).
        
19. **Оптимизация запросов**
    
    - **План выполнения (Execution Plan)**:
        
        - **EXPLAIN PLAN FOR запрос**: сохранение плана выполнения в таблице PLAN_TABLE; последующий просмотр через SELECT *.
            
        - **AUTOTRACE**: вывод плана выполнения и статистики, помогает оптимизировать запросы.
            
    - **Статистика**:
        
        - **DBMS_STATS.GATHER_SCHEMA_STATS**: сбор статистики по таблицам и индексам; обновление выборочных данных.
            
        - **Влияние статистики**: планировщик использует статистику для оценки кардинальности и выбора оптимального пути.
            
    - **Индикаторы эффективности**:
        
        - **Кардинальность**: оценка числа строк после выполнения операций;
            
        - **Selectivity**: селективность условий;
            
        - **Cost-based Optimization**: выбор плана с минимальной стоимостью.
            
    - **Подсказки (Hints)**:
        
        - **/*+ INDEX(table index_name) */**: указание индекса.
            
        - **/*+ FULL(table) */**: принудительное полное сканирование.
            
        - Другие: USE_NL, USE_HASH, FIRST_ROWS, оптимизация соединений.
            
20. **Специфические особенности Oracle SQL**
    
    - **TIMESTAMP WITH TIME ZONE**: хранение времени с учётом часового пояса, синхронизация данных между географически распределёнными системами.
        
    - **Семантика LOB**:
        
        - **CLOB/NCLOB/BLOB**: различия, ограничения по размеру.
            
        - **Методы доступа**: DBMS_LOB.EXTRACT, DBMS_LOB.APPEND, операции IN-PLACE.
            
        - **Дефрагментация и хранение**: SecureFiles vs BasicFiles, компрессия, deduplication.
            
    - **NLS-настройки**:
        
        - **NLS_LANG**: языковой и региональный пакеты клиента.
            
        - **NLS_DATE_FORMAT, NLS_TERRITORY, NLS_SORT**: параметры отображения дат, формат чисел, сортировка.
            
    - **Партиционирование**:
        
        - **Range, List, Hash, Composite**: способы разделения больших таблиц на части.
            
        - **Преимущества**: управление данными по диапазонам, улучшение производительности при сканировании.
            
    - **Materialized Views (Материализованные представления)**:
        
        - **Создание**: CREATE MATERIALIZED VIEW имя AS SELECT ... [BUILD IMMEDIATE | BUILD DEFERRED] [REFRESH ...];
            
        - **Режимы обновления**: полное (COMPLETE), инкрементное (FAST), принудительное (FORCE), ON DEMAND/ON COMMIT.
            
        - **Использование**: ускорение отчётов, агрегация больших объёмов данных.

## Ключевые разделы и расширенные описания (около 80% от оригинала)

- **Общие сведения о SQL**:  
    SQL — язык для работы с реляционными базами; включает DDL, DML, DCL и TCL. Архитектура: клиентские утилиты (SQL*Plus, SQL Developer и др.) связаны с сервером через сетевой протокол. Сервер хранит данные, метаданные, статистику и обрабатывает запросы.
    
- **Типы данных**:  
    Числовые типы позволяют хранить как целые, так и дробные значения с высокоточной арифметикой; символьные важны для хранения текстов и символов разных кодировок; типы DATE и TIMESTAMP обеспечивают точную работу с датами и временем, поддерживают арифметику и извлечение компонентов; LOB для больших объёмов, XMLType для полуструктурированных данных; RAW хранит бинарные последовательности, полезен для хешей, образов.
    
- **DDL**:  
    CREATE ___ предоставляет полное описание структуры объекта: в CREATE TABLE указываются имена столбцов, типы данных, ограничения (PK, FK, UNIQUE, CHECK). При создании индекса можно указывать уникальность, направление сортировки (ASC/DESC), Tablespace. ALTER TABLE позволяет динамически модифицировать таблицу без её пересоздания: добавлять столбцы, изменять типы (с возможными преобразованиями), добавлять/удалять индексы, ограничения. DROP TABLE полностью удаляет таблицу и её данные, возможен автоматический нюд результатов через FLASHBACK (если включено); DROP VIEW, DROP INDEX, DROP SYNONYM освобождает используемые ресурсы (пространство, ссылки).
    
- **DML**:  
    SELECT часто используется с ключом DISTINCT для удаления дубликатов, с ключевым словом ALL (по умолчанию) для получения всех строк. Параметр FETCH FIRST n ROWS ONLY (ANSI SQL) или ROWNUM (Oracle) ограничивает число результатов. Подзапросы могут быть встроены в SELECT: скалярные, табличные. INSERT поддерживает опцию /*+ APPEND */ для прямой загрузки (Direct-Path Insert), пропускающей буфер OR buffer cache. UPDATE можно комбинировать с RETURNING INTO для получения обновлённых значений. DELETE поддерживает опцию WHERE EXISTS для проверки наличия связанных строк. MERGE снижает количество DML-операций, полезен при загрузке больших объёмов.
    
- **Подзапросы**:  
    Некоррелированные используются, когда результат можно определить заранее (до основного запроса), например, вычисление среднего и сравнение с ним. Коррелированные применяются, когда необходимо связывать каждую строку с агрегированной информацией или проверять условия в зависимости от текущей строки. EXISTS генерирует короткое замыкание: если хотя бы одна строка найдена, дальнейшее сканирование прекращается.
    
- **Объединения**:  
    UNION приводит к дополнительным затратам на сортировку и удаление дубликатов. UNION ALL быстрее, но требует дополнительной обработки дубликатов на прикладном уровне. INTERSECT и MINUS используют внутренние алгоритмы (Hash или Merge), зависящие от наличия индексов. Для каждого набора результаты должны иметь одинаковую структуру: одинаковое число столбцов и совместимые типы (необязательно одинаковые имена).
    
- **JOIN**:  
    INNER JOIN может оптимизироваться до Nested Loops, Hash Join или Sort-Merge Join в зависимости от селективности и статистики. LEFT/RIGHT OUTER JOIN представляют собой расширение INNER: сохраняют дополнительные строки, добавляют NULL. FULL OUTER JOIN трудоёмкий, редко используется на больших наборах. CROSS JOIN без условий часто используется при генерации тестовых данных или математических задачах (комбинации). SELF-JOIN требует двойного упоминания таблицы с алиасами (t1, t2), часто используется для задач иерархии или сравнения строк в той же таблице.
    
- **Агрегаты и GROUP BY/HAVING**:  
    Агрегатные функции допускают фильтрацию результатов: COUNT(DISTINCT col), SUM(DISTINCT col). GROUP BY поддерживает выражения и функции, формируя группы по вычисленным значениям. HAVING может содержать те же агрегатные функции или простые выражения. Порядок исполнения: WHERE фильтрует отдельные строки, GROUP BY объединяет, HAVING фильтрует группы.
    
- **Функции и выражения**:  
    Строковые функции позволяют обрабатывать текстовые данные без использования процедур: INSTR находит позицию подстроки, LPAD/RPAD заполняют до заданной длины. Числовые функции: MOD вычисляет остаток, POWER возводит в степень, TRUNCATE удаляет дробную часть без округления. Дата/время: NEXT_DAY находит следующий указанный день недели, LAST_DAY возвращает конец месяца, SYSDATE возвращает дату без часовой зоны (локальная). CASE часто применяется для создания вычисляемых атрибутов, упрощая сложные условия.
    
- **Представления**:  
    Обеспечивают уровень абстракции: упрощают сложные запросы, скрывают сложную логику, отделяют пользователей от изменений в базе. Режим WITH READ ONLY запрещает DML через VIEW. MATERIALIZED VIEW (описано в разделе 20) хранят результаты на диске и обновляются по расписанию.
    
- **Индексы**:  
    Использование Bitmap-индексов оправдано при низкой кардинальности (меньше 1000 уникальных значений). Для OLTP систем предпочтительны B-tree. Составные индексы оптимизируют запросы по нескольким условиям. Функциональные индексы (операции над столбцом, например UPPER(col)). При создании индексов учитывают кластеризацию (CLUSTER INDEX). Мониторинг: V$OBJECT_USAGE показывает использование индекса.
    
- **Constraints**:  
    Констрейнты можно задавать при создании таблицы: констрейнт именуется по соглашениям. FOREIGN KEY может иметь опции ON DELETE SET NULL/SET DEFAULT. CHECK применяется для бизнес-правил (диапазон зарплат, даты рождения). Если констрейнт нарушается, операция aborts с ошибкой.
    
- **Транзакции и управление ими**:  
    Уровни изоляции влияют на читаемость «грязных» данных: READ COMMITTED — не показывает непро-фиксированные изменения, READ UNCOMMITTED — показывает (Oracle использует только READ COMMITTED и SERIALIZABLE). SERIALIZABLE обеспечивает полную изоляцию, но возможны блокировки и взаимные блокировки (deadlocks). Автоматический COMMIT в командах DDL и некоторых DML.
    
- **Секвенции**:  
    При параллельном доступе несколько сессий получают следующий номер без блокировок. Параметр CACHE настраивает буферизацию значений для ускорения, но при сбоях часть номеров может «потеряться». CYCLE позволяет возобновить последовательность после достижения MAXVALUE. ORDER обеспечивает генерацию последовательных значений в порядке реального времени в RAC-кластере.
    
- **Синонимы**:  
    Упрощают миграцию между схемами, абстрагируют логику от физического расположения. PUBLIC SYNONYM используется для часто вызываемых объектов, требующих единого имени при множестве схем. При удалении базового объекта обращение через синоним становится ошибочным.
    
- **Триггеры**:  
    BEFORE-триггеры часто используются для проверки и модификации значений (например, автоматическое заполнение полей). AFTER — для логирования: запись изменений в стороннюю таблицу audit. INSTEAD OF применяются для обновления сложных VIEW, трансляции операций DML на несколько таблиц. Триггеры могут вызывать процедуры и функции, но чрезмерное использование влияет на производительность.
    
- **Нормализация данных**:  
    Примерные сценарии:
    
    - Разделение контактной информации в отдельную таблицу (1NF), чтобы избежать повторения.
        
    - Выделение справочников для справочных атрибутов (2NF), чтобы избавиться от частичных зависимостей от составного ключа.
        
    - Устранение транзитивных зависимостей (3NF): если A → B и B → C, то перенос C в отдельную таблицу, чтобы B не определял C.
        
- **Права доступа и безопасность**:  
    Рекомендации:
    
    - Использовать роли для группировки прав, назначать пользователям только нужные роли.
        
    - Пароли должны соответствовать политике безопасности (минимальная длина, сложность, срок действия).
        
    - Профили ограничивают ресурсы: IDLE_TIME, CONNECT_TIME, SESSIONS_PER_USER.
        
- **Оптимизация запросов**:
    
    - **Index Monitoring**: включение мониторинга для проверки используемых индексов.
        
    - **SQL Tuning Advisor**: автоматизированный инструмент для рекомендаций по оптимизации.
        
    - **TKPROF**: утилита для анализа трассировки SQL, определяет узкие места (I/O, CPU).
        
- **Специфические особенности Oracle SQL**:
    
    - **Партиционирование**: Range Partition по дате для разделения исторических данных, List Partition для категориальных данных, Hash Partition для равномерного распределения нагрузки; Composite Partition сочетает методы.
        
    - **Materialized Views**: ускоряют отчёты; при FAST REFRESH требуется наличие материальных индексов и информации о логах изменений (Materialized View Logs).
        
    - **Oracle Multitenant**: архитектура контейнеров CDB/PDB, возможность мультиарендности и изоляции баз.
