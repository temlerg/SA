# 📌 CI/CD — теоретическая база (лекция)

**CI/CD** (Continuous Integration / Continuous Delivery или Deployment) — это набор практик и процессов, направленных на автоматизацию сборки, тестирования и доставки программного обеспечения. Цель — ускорить и упростить выпуск новых версий без потери качества.

---

## 📘 Термины и расшифровка

- **CI (Continuous Integration)** — непрерывная интеграция
    
    - Каждый коммит в кодовую базу автоматически проверяется, собирается и тестируется
        
- **CD (Continuous Delivery)** — непрерывная доставка
    
    - Автоматическая сборка и тестирование приложения до готовности к выкатке в продуктив
        
    - Развёртывание требует ручного подтверждения
        
- **CD (Continuous Deployment)** — непрерывный деплой
    
    - То же, что и Continuous Delivery, но с автоматической доставкой на продакшн без участия человека
        

---

## 🧠 Зачем нужны CI/CD

- Сокращение времени между изменением и доставкой результата пользователю
    
- Быстрое обнаружение и устранение ошибок
    
- Повышение стабильности и повторяемости релизов
    
- Меньше ручных действий → меньше человеческих ошибок
    

---

## 🧱 Компоненты CI/CD процесса

1. **Репозиторий кода (SCM)**
    
    - GitHub, GitLab, Bitbucket, Azure DevOps
        
2. **CI-сервер** (оркестратор)
    
    - Jenkins, GitHub Actions, GitLab CI, CircleCI, Travis, TeamCity
        
3. **Сценарии/пайплайны (pipeline)**
    
    - YAML/DSL-описания этапов: билд → тест → деплой
        
4. **Автоматические тесты**
    
    - Unit, Integration, E2E
        
5. **Среда развёртывания**
    
    - Staging, production, docker/k8s, виртуалки, облака
        
6. **Уведомления и логирование**
    
    - Slack, Email, Telegram + логи пайплайнов
        

---

## 🔄 Жизненный цикл CI/CD

```text
Git push → CI запускает билд → Автотесты → Сборка артефактов (бинарники, docker) → CD выкатывает в среду
```

Каждое изменение кода «живо» проходит полный цикл, верифицируется, и (в случае success) попадает в рабочую среду.

---

## 🔧 Пример пайплайна (на YAML, GitLab CI)

```yaml
stages:
  - build
  - test
  - deploy

build:
  stage: build
  script:
    - npm install
    - npm run build

test:
  stage: test
  script:
    - npm run test

deploy:
  stage: deploy
  script:
    - ./deploy.sh
  only:
    - main
```

## 📊 Метрики и эффективность

- Time to Deploy
    
- Number of Deploys per day
    
- Deployment Success Rate
    
- Rollback Frequency
    

---

## ✅ Преимущества внедрения CI/CD

- Быстрая доставка фич
    
- Повышение качества кода (через тесты и проверки)
    
- Прозрачность и контроль
    
- Устранение узких мест и «ручного ада»
    

---

## 🚫 Потенциальные проблемы

- Неподготовленность к автоматизации (хаотичный код)
    
- Отсутствие автотестов → пользы от CI почти нет
    
- Плохая сегментация окружений (dev/test/prod)
    
- Большие монолиты → медленные пайплайны
