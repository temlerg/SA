# 📌 Методология Waterfall (каскадная модель)

**Waterfall** — это классическая модель жизненного цикла разработки ПО, в которой каждая стадия проекта выполняется строго последовательно. Каждая следующая фаза начинается только после завершения предыдущей.

---

## 🔧 Этапы Waterfall

1. **Сбор и анализ требований**
    
    - Формулируются все требования к системе заранее
        
    - Результат: документ требований (SRS)
        
2. **Проектирование системы**
    
    - Создаются архитектурные схемы, модели данных, интерфейсы
        
    - Разработка технической документации
        
3. **Реализация (кодирование)**
    
    - Программисты пишут код на основе проектной документации
        
4. **Тестирование**
    
    - Проверка соответствия системы спецификациям
        
    - Верификация, отладка, устранение багов
        
5. **Внедрение**
    
    - Развёртывание системы на продуктивной среде
        
    - Обучение пользователей
        
6. **Сопровождение и поддержка**
    
    - Исправление ошибок, внесение ограниченных изменений
        
    - Обновления в случае необходимости
        

---

## ✅ Преимущества Waterfall

- Простота и логичность этапов
    
- Хорошая документированность и контроль
    
- Удобен для небольших или формализованных проектов
    
- Чёткая последовательность, минимизация хаоса
    

---

## 🚫 Недостатки Waterfall

- Плохо подходит для проектов с изменяющимися требованиями
    
- Ошибки обнаруживаются поздно — на этапе тестирования
    
- Сложно возвращаться к предыдущим этапам
    
- Нет обратной связи с пользователями в процессе
    

---

## 📌 Когда использовать Waterfall

- Когда требования понятны и стабильны
    
- В проектах с жёстким регуляторным контролем (гос., банковская сфера)
    
- При необходимости полной документации до начала работ
    

---

## 📊 Сравнение с Agile (в общих чертах)

| Критерий           | Waterfall           | [[Agile]]                          |
| ------------------ | ------------------- | ---------------------------------- |
| Последовательность | Строго по этапам    | Итеративная, инкрементальная       |
| Гибкость           | Низкая              | Высокая                            |
| Документирование   | Жёсткое и заранее   | Минимальное, по мере необходимости |
| Обратная связь     | На финальных этапах | Постоянная (спринты, демо)         |
| Изменения          | Трудно вносить      | Внедряются гибко и быстро          |
