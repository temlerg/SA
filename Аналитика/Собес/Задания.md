## 1. SQL - задачка про машины

Таблица owners – владельцы автомобилей: id (уникальный идентификатор владельца), fio (ФИО одной строкой). Таблица cars – автомобили: id (уникальный идентификатор автомобиля), owner_id (внешний ключ на владельца), manufacturer (производитель автомобиля – BMW, Audi, Mercedes и т.д.). Все столбцы обязательны. У каждого владельца может быть от 0 до бесконечности автомобилей. Нужно написать запрос, который бы выдал ФИО всех владельцев, у которых есть BMW и Audi (то есть тех, где у одного и того же владельца есть как минимум одна BMW и как минимум одна Audi).
**Решение:**
-v1
select distinct o.fio
from cars c join owners o
on c.owner_id = [o.id](http://o.id/)
where c.owner_id in (SELECT owner_id
FROM cars
WHERE manufacturer = 'BMW') and
owner_id in (SELECT owner_id
FROM cars
WHERE manufacturer = 'Audi');
--v2
select distinct o.fio
from (select *
from cars
where manufacturer = 'Audi') cA join
(select *
from cars
where manufacturer = 'BMW') cB
on cA.owner_id = cB.owner_id
join owners o on cB.owner_id = [o.id](http://o.id/);
--v3
SELECT o.fio
FROM owners o
JOIN cars c
on [o.id](http://o.id/) = c.owner_id
GROUP BY o.fio
HAVING sum(case c.manufacturer when 'Audi' then 1 else 0 end)>0 AND
sum(case c.manufacturer when 'BMW' then 1 else 0 end)>0;

## 2. Интеграции - синхронизация данных в двух системах

Есть две системы: основная и модуль. В основной хранятся данные о договорах и клиентах, в модуле хранятся данные о договорах. Данные в обеих системах различны (даже в договорах хранятся разные параметры). Сейчас данные обновляются следующим образом: раз в определенный промежуток времени данные из основной системы выгружаются в exсel табличку. После чего данные переотправляются по почте сотрудникам, которые работают с модулем. Они загружают данные в модуль и процесс завершается. Аналогично данные отправляются в обратную сторону (из модуля в основную систему). 

Всем надоело так работать и они хотят, чтобы при обновлении данных в одной системе (если пользователь отредактрировал данные, например) - данные во второй системе сразу же обновлялись. Как это сделать? Какой подход к решению задачи будешь использовать? Что делать в случае, когда системы параллельно обновляют ресурсы (например, пока нам в модуль отправляют новые данные, мы в то же время отправляем данные в основную систему)?

**Решение:**

Необходимо разделить все объекты на сущности. У каждой сущности будет такой объект как ключ. Ключ - отдельная таблица, там находится состояние этой сущности, время последнего обновления и так далее. Потом, когда происходит конфликт, то у каждой сущности будет свой механизм разрешения конфликта (где-то это мастер/слейв система, где-то это самая последняя запись будет учитываться)
