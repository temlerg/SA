# 📌 Apache Kafka — архитектура и применение

**Apache Kafka** — это распределённая платформа потоковой передачи данных (streaming platform), разработанная для публикации, хранения, обработки и подписки на потоки событий в реальном времени.

Kafka изначально была создана в LinkedIn и стала де-факто стандартом для построения событийно-ориентированных систем и потоковой интеграции микросервисов.

---

## 🧠 Основные концепции

- **Producer (производитель):** отправляет события (сообщения) в Kafka
    
- **Consumer (потребитель):** читает события из Kafka
    
- **Topic:** категория или канал, в который публикуются сообщения
    
- **Partition:** топик делится на разделы (partitions) для масштабируемости
    
- **Broker:** сервер Kafka, обрабатывающий данные
    
- **Cluster:** группа брокеров, работающих вместе
    
- **Consumer Group:** группа потребителей, обрабатывающих топик совместно
    

---

## ⚙️ Архитектура Kafka

1. Продюсеры публикуют сообщения в **топики**, разбитые на **партиции**
    
2. Сообщения в каждой партиции сохраняются в журнал в порядке поступления
    
3. Консьюмеры читают сообщения по смещению (offset) — то есть могут обрабатывать в своём темпе
    
4. Kafka сохраняет сообщения на диск (не теряет их при сбое)
    
5. Репликация данных между брокерами обеспечивает надёжность
    

---

## ✅ Преимущества Kafka

- Высокая производительность (миллионы сообщений в секунду)
    
- Надёжность и устойчивость к сбоям
    
- Масштабируемость по горизонтали
    
- Поддержка как реального времени, так и отложенной обработки
    
- Взаимодействие с большими экосистемами (Flink, Spark, Hadoop, ClickHouse)
    

---

## 🚀 Типовые сценарии использования

- Событийная архитектура (EDA) в микросервисах
    
- Стриминг логов и метрик
    
- Отслеживание кликов и действий пользователей
    
- Финансовые транзакции и платёжные шины
    
- Сбор телеметрии от устройств IoT
    
- Буфер между системами при интеграции

- Авторизация на уровне топиков

## 📦 Интеграции и экосистема

- **Kafka Connect** — синхронизация с БД, REST, облаками
    
- **Kafka Streams** — библиотека для обработки потоков внутри Java-приложений
    
- **ksqlDB** — SQL-подобный язык для стриминга
    
- **Confluent Platform** — расширение Kafka с UI, схемами, REST-проксей и мониторингом

### 🗺 Архитектурная схема Kafka-кластера (текстово)

```
               +----------------+
               |   Producer 1   |
               +----------------+
                        |
               +----------------+
               |   Producer 2   |
               +----------------+
                        |
                    [Kafka Topic]
              /         |         \
         [Partition 0] [Partition 1] [Partition 2]
              |              |              |
         +----------+  +----------+   +----------+
         | Broker 1 |  | Broker 2 |   | Broker 3 |
         +----------+  +----------+   +----------+
              |              |              |
       +--------------+ +--------------+ +--------------+
       | Consumer Grp1| | Consumer Grp2| | Consumer Grp3|
       |  Consumer A  | |  Consumer B  | |  Consumer C  |
       +--------------+ +--------------+ +--------------+
```

Kafka-кластер обычно состоит из нескольких брокеров, каждый из которых отвечает за хранение и обслуживание одной или нескольких партиций. Продюсеры публикуют события в топики, а группы консьюмеров читают их асинхронно. Система масштабируется горизонтально и обеспечивает отказоустойчивость через репликацию партиций.
