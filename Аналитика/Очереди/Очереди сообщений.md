| ----------------- | ----------------------------------------------- |
| [[Kafka]]         | Надёжна, масштабируема, disk-based log          |
| [[RabbitMQ]]      | Подходит для очередей, меньше для стриминга     |

> Apache Kafka и RabbitMQ — это два решения для обмена сообщениями, но они решают принципиально разные задачи, и архитектурно сильно различаются.
> 
> Kafka — это распределённый commit log, ориентированный на **работу с потоками данных и хранение истории событий**. Он реализует модель _publish/subscribe_, в которой сообщения сохраняются на диск, не удаляются после получения и могут быть прочитаны разными потребителями в разное время. Это делает Kafka идеальным для **Big Data**, **stream processing**, **event sourcing** и **анализов в реальном времени**.
> 
> В отличие от него, RabbitMQ реализует классическую модель **message broker’а** — с очередями, роутингом, подтверждением доставки и удалением сообщений после получения. Он построен по протоколу AMQP, отлично подходит для **микросервисной архитектуры**, **интеграции приложений**, **работы с задачами и push-уведомлениями**. У него выше гибкость маршрутизации, но ниже производительность при больших объёмах данных.
> 
> Если кратко: Kafka — это **журнал событий**, RabbitMQ — **интеллектуальный брокер с очередями**. Kafka выбирают, когда важна масштабируемость и история сообщений; RabbitMQ — когда критична мгновенная доставка и сложная маршрутизация.

> При выборе я бы ориентировался на целевую архитектуру: для аналитических платформ и телеметрии — Kafka; для типичной распределённой системы — RabbitMQ.
