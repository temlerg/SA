## 🔐 JWT (JSON Web Token)##

**JWT** — это компактный, URL-безопасный способ передачи информации между двумя сторонами в виде JSON-объекта, который может быть проверен и доверен благодаря цифровой подписи.

### 🔧 Структура JWT:

Состоит из трёх частей, разделённых точками:

```
<Header>.<Payload>.<Signature>
```

- **Header**: тип токена (обычно `"JWT"`) и алгоритм подписи (`HS256`, `RS256`)
    
- **Payload**: полезная нагрузка (например, `user_id`, `role`, `exp`) — данные, которые получатель должен получить
    
- **Signature**: цифровая подпись (обычно HMAC или RSA)
    

### 📌 Пример:

```
eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9
.
eyJ1c2VySWQiOjEyMywiZXhwIjoxNzAwMDAwMDB9
.
sdfsdf-asfasfasfasd-234234
```

### 📋 Типовой сценарий:

1. Пользователь логинится → сервер выдаёт JWT
    
2. Клиент хранит JWT (в `localStorage`, `sessionStorage`, cookie)
    
3. При каждом запросе → отправляет JWT в заголовке:
    
    ```
    Authorization: Bearer <jwt-token>
    ```
    

### ✅ Преимущества:

- Безопасность (если правильно реализовано)
    
- Стандартизирован и широко поддерживается
    
- Удобен для SPA и микросервисов
    

### ⚠️ Важно:

- Не храните чувствительные данные в payload — он не шифруется
    
- Проверяйте `exp` (время жизни токена)
    
- Используйте HTTPS — иначе токен могут перехватить
