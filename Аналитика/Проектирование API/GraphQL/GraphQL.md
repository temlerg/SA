GraphQL — это язык запросов к API и среда выполнения этих запросов, разработанный компанией Facebook в 2015 году. Он предоставляет альтернативу REST и ориентирован на точную выборку только необходимых данных. В отличие от REST, где структура ответа жёстко задана сервером, в GraphQL клиент сам описывает нужные поля и вложенности, а сервер возвращает строго запрошенные данные.

---

## 🧠 Принцип работы GraphQL

GraphQL работает на основе **схемы**, которая описывает все возможные типы данных, операции и связи между сущностями. Схема служит контрактом между клиентом и сервером.

Клиент отправляет **запрос** в виде строки (на языке GraphQL), а сервер:

1. **Парсит запрос**
    
2. **Проверяет его валидность** по схеме
    
3. **Выполняет резолверы** — функции, отвечающие за получение данных
    
4. **Формирует JSON-ответ** строго по структуре запроса
    

Таким образом, GraphQL — это не просто формат, а **исполняемая схема**, реализующая строгий типизированный контракт.

---

## ⚙️ Архитектура GraphQL API

### Компоненты:

- **Schema** — описание типов, запросов, мутаций, подписок
    
- **Query Executor** — механизм выполнения валидных запросов
    
- **Resolver Functions** — функции, которые отвечают за возврат конкретных данных
    
- **Context** — объект с пользовательскими данными (например, авторизация), доступный в каждом резолвере
    
- **Middleware/Directives** — надстройки для добавления логики (например, авторизация, логгинг)
    

---

## 🔎 Типизация и строгая структура

GraphQL требует **обязательной типизации**:

- Все поля имеют типы (`String`, `Int`, `Boolean`, `User`, `[Post]` и т.д.)
    
- Можно задавать обязательные (`!`) или опциональные поля
    
- Отношения выражаются через вложенные типы
    
- Ошибки в запросах выявляются до выполнения (на этапе валидации)
    

---

## 📐 Уровни доступа к данным

GraphQL позволяет централизованно управлять логикой доступа:

- Через резолверы (например, `if (!context.user.isAdmin) throw Forbidden`)
    
- Через директивы (`@auth(role: "admin")`)
    
- Через отдельные middleware (в Apollo Server и др.)
    

---

## 🔄 Резолверы (Resolvers)

Резолвер — это функция, которая:

- Получает аргументы и контекст
    
- Выполняет доступ к данным (БД, API, кэш)
    
- Возвращает результат, который сериализуется в JSON
    

Пример на JavaScript:

```js
const resolvers = {
  Query: {
    user: (_, { id }) => getUserById(id)
  }
};
```

---

## 🔧 Интроспекция и автогенерация

GraphQL поддерживает **интроспекцию** — возможность запроса самой схемы через специальный meta-запрос. Это делает возможной:

- Автоматическую генерацию документации
    
- Интеграцию с GraphQL IDE (GraphiQL, Apollo Studio)
    
- Генерацию типизированных клиентов (например, TypeScript + GraphQL Codegen)
    

---

## 🔄 Вложенные запросы и агрегации

GraphQL позволяет за один запрос:

- Получить данные с множественной вложенностью (`user → posts → comments → author`)
    
- Выполнить несколько независимых выборок параллельно (в одном запросе)
    
- Избежать дублирования данных за счёт повторного использования фрагментов (`...FragmentName`)
    

---

## 📤 Ответы и структура ошибок

- Все ответы приходят в JSON, даже ошибки
    
- Структура:
    

```json
{
  "data": { ... },
  "errors": [
    {
      "message": "Field not found",
      "path": ["user", "email"],
      "extensions": { "code": "GRAPHQL_VALIDATION_FAILED" }
    }
  ]
}
```

- Поле `data` может быть `null`, если ошибка критическая
    

---

## 📚 Разделение схемы

- **Query** — только чтение
    
- **Mutation** — действия, изменяющие данные
    
- **Subscription** — события в реальном времени (через WebSocket)
    

---

## 🌐 Гибкость при развитии

GraphQL хорошо масштабируется и позволяет:

- Добавлять поля без нарушения существующих клиентов
    
- Отслеживать неиспользуемые поля
    
- Объявлять устаревшие поля через директиву `@deprecated`
